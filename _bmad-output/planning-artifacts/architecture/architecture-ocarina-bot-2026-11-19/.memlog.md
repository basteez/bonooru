- (decision) heartbeat encoding: bridge emits a real CRC-checked frame HEARTBEAT (type 0x40, link range) every 20 ms with body bridge_fw_ver[3] + flags (bit0 = CDC DTR asserted); not an empty COBS frame, because a lone 0x00 from line noise would feed the watchdog and could not carry the bridge version
- (decision) bridge PC->UART path is store-and-forward per COBS frame: it scans only for 0x00 delimiters (no decoding), forwards whole frames atomically, injects HEARTBEAT between them. Prevents host stalls mid-frame (case C) from starving the heartbeat and prevents heartbeat bytes landing inside an app frame. Overlong run without delimiter (> 300 bytes) is dropped and counted
- (decision) frame type ranges: 0x01-0x3F app->controller, 0x40-0x7F bridge->controller (link-local, never forwarded to app, never ACKed), 0x80-0xFF controller->app
- (decision) reliability: go-back-N on seq (u8): controller accepts only seq == expected; duplicate (expected-1) is re-ACKed with no side effect; other seq -> NAK(SEQ, expected). HELLO resets expected to its seq+1. App on NAK or ACK timeout resends from expected. Prevents duplicate or missing QUEUE_EVENTs after UART noise
- (decision) protocol version: PROTO_VERSION u8 exact match required (no negotiation). HELLO body and the first byte of INFO (proto_ver) are frozen forever; controller always answers HELLO with INFO, and NAKs (VERSION) every other app frame until a matching HELLO. Single source shared by both codecs = protocol test vectors file
- (decision) INFO body (v1): proto_ver u8, fw_ver[3] (major,minor,patch), bridge_ver[3] from last HEARTBEAT (0,0,0 if none), profile u8, queue_cap u16, app_timeout_ms u16. App pings when idle >= app_timeout_ms/4 in direct mode; firmware owns the timeout value
- (decision) end of piece: state.flags bit0 = END on the last QUEUE_EVENT; applying it ends playback (IDLE, EVENT PLAYBACK_DONE). Queue empty while PLAYING without END = underrun: neutral, queue cleared, mode IDLE, EVENT UNDERRUN. Other flags bits reserved = 0
- (decision) controller modes IDLE / DIRECT / PLAYING owned by core 1: SET_STATE allowed in IDLE/DIRECT (enters DIRECT), NAK BUSY in PLAYING; QUEUE_EVENT allowed in IDLE/PLAYING; START from IDLE or DIRECT (real-time state cleared); STOP from any -> neutral, queue cleared, IDLE.
