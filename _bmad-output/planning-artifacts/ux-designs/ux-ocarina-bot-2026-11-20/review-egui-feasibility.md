# Review: egui feasibility of the UX spines (adversarial)

Date: 2026-11-20. Scope: `DESIGN.md`, `EXPERIENCE.md`, `.working/directions-oot-2026-11-20.html` (direction 3 "Hybrid"), checked against the stack actually pinned by the spike: **eframe/egui/epaint 0.37.0, winit 0.30.13, wgpu backend** (`spikes/app-egui/Cargo.toml`). Claims about egui behaviour were verified in the crate sources in `~/.cargo/registry` (file references below), not from memory or docs for older versions.

Verdicts: **feasible** = standard egui API or a small custom widget (< ~1 day); **costly** = doable but needs non-obvious plumbing, a helper library, a workaround, or a spine wording change to stay cheap; **infeasible** = cannot be done as specified (by egui or by arithmetic).

## Key facts from the 0.37 sources (they drive several verdicts)

- **Glow exists for rectangles.** `epaint::Shadow { offset, blur, spread, color }` and `RectShape::blur_width` (`epaint/src/shadow.rs`, `shapes/rect_shape.rs`) give a real soft penumbra. With offset 0 and an amber/ember colour this is a CSS `box-shadow` glow. Works for any rounded rect, so also circles (full radius). **No blur for text, arbitrary paths, or inset shadows.**
- **Filled paths must be convex** (`shapes/path_shape.rs:16`, `tessellator.rs` fan triangulation). Strokes work on any path. Dashes: `Shape::dashed_line(_many)`; curves: `QuadraticBezierShape` / `CubicBezierShape`.
- **Text shaping is harfrust + skrifa with variable-font support**: `RichText::variation("wght", 700.0)` / `TextFormat::coords`, plus `extra_letter_spacing`, `line_height`, `underline`. But shaping uses `ShapeOptions::new()` with **no OpenType feature list** (`text_layout.rs:1605`), so `tnum` etc. cannot be switched on. `RichText::strong()` only changes colour; there is no synthetic bold.
- **Focus**: arrow keys and Tab move egui focus, and Esc clears it, in `Memory::begin_pass` *before* app code runs, unless the focused widget set an `EventFilter` via `set_focus_lock_filter` (`memory/mod.rs:569-610, 908`). Clicking does not give focus (except TextEdit); pressing elsewhere surrenders it (`context.rs:1844`). A focused widget is "clicked" by **Space or Enter** (`context.rs:1761`). Focus is drawn with the *active* (pressed) visuals, not a distinct ring (`style.rs:1386`). Tab order = widget registration order, and `CentralPanel` must be added last (`containers/panel.rs:14`).
- **Esc is not consumed** by TextEdit or focus handling; `Modal::should_close()` *does* consume it (`containers/modal.rs:156`).
- **winit 0.30.13 has no file drag-and-drop on Wayland**: `DroppedFile`/`HoveredFile` are emitted only by the macOS, Windows and X11 backends (`winit/src/platform_impl/...`). eframe enables both `wayland` and `x11` by default, so a Wayland session runs natively and drops nothing.

## Recommended spine edits by severity

### Critical
- None. Nothing in the spines forces leaving egui.

### High
1. **Split-view height (#39).** At the 1024 × 680 minimum, the text-score split cannot show 19 lanes + zones. Add a rule to DESIGN › Layout and EXPERIENCE › Responsive (vertical scroll in the lane area, collapsible out-of-range zones, or resizable split with an editor min height).
2. **Gamepad keyboard focus model (#23).** EXPERIENCE should define gamepad focus as egui focus on the panel with an arrow/Esc event filter, child controls non-focusable, keys matched by physical position. Without this the D-pad arrows will move egui focus instead of pressing the D-pad.
3. **Space vs focused buttons (#27).** EXPERIENCE › Context shortcuts: Space is consumed for preview outside editor/gamepad; buttons activate with Enter only. Otherwise Space on a focused "Play from cursor" starts Play.
4. **Undo + roll→text rewrite (#29).** Close Open Question 8: one app-level undo history, external rewrites reset TextEdit's undoer, roll edits rewrite only the affected tokens with caret preserved.
5. **Linux file drop (#42/#45).** EXPERIENCE › Platform › Linux: ship with X11/XWayland (eframe without `wayland`), or say drop is unavailable on Wayland. Flow 2 depends on it.

### Medium
6. **Silhouette fill (#8).** DESIGN: "union of convex shapes + one stroked outline", not "one closed path".
7. **Glyph coverage (#5).** DESIGN: draw ⌫ ↵ ↑ ♯ ♪ as Painter shapes or use ASCII forms; verify the chosen TTFs' coverage.
8. **Focus ring spec (#24).** EXPERIENCE › Accessibility: define one ring style and require it in every widget helper (egui has no default ring and no focus-visible).
9. **Playhead during Play (#33).** EXPERIENCE › Hardware coupling: interpolate between 20 Hz `now_us` updates.
10. **Glow technique (#9, #10).** DESIGN › Elevation: allow `Shadow`/`blur_width` for rect/circle glow; turn the countdown text glow into a soft halo or drop it.

### Low
11. **Tabular figures (#4):** fixed-width digit cells or Hack for times.
12. **Weights (#2):** variable `wght` axis; `.strong()` is not bold; trim unused weights.
13. **Tab order (#46):** manual region layout if the documented order matters.
14. **Hairlines (#32):** floor at 1 physical px.
15. **Minimum size (#38):** stated in logical points; note high-scale small laptops.
16. **Native pieces (#45):** name `rfd`; accept CSD on Wayland.
17. **AccessKit (#52):** decide whether helpers emit `widget_info` from the start.
18. **Note-editing gestures (#30):** spell out "drag empty = pan, drag note = move".
