# Story 4.7: STOP, Esc and the bottom bar

Status: in-progress

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As the owner,
I want a big STOP that always works, also from the keyboard,
so that I can release every input instantly whatever the app is doing.

Origin: `epics.md` Epic 4, Story 4.7 (UX-DR39 in its Epic 4 form: STOP and the safety note, empty Play/Listen slots; UX-DR41 STOP always enabled, Esc anywhere; UX-DR61 Esc read at frame start, Space consumed at frame start, buttons Enter only, Tab order; UX-DR62 no Space activating buttons, focus always visible; AD-6, AD-8, AD-16). It builds on Story 4.3 (`ui::modal::Modals` and its Esc contract: Esc is read by this story at the top of the frame and not consumed, the open dialog then consumes it; `paint_focus_ring`; `symbols::Symbol::Stop`; the basic AccessKit level), 4.4 (the serial worker, `WorkerCommand`, the `LogHandle` lines), 4.5 (the focusable LEDs that come first in the Tab ring; the bench rig block format, H.33) and 4.6 (`App::ui` with the Esc comment at its top, the first-pass-only drain and `request_discard`, `ModalSpec::ignoring_opening_esc`, C.27 "nothing written while incompatible"). It carries the Epic 3 retro rules E3-A1 (AC → measurement table below), E3-A2 (no bench tool is new or changed; the new `stop` log lines are the bench instrument and each verdict they can show has a host test that proves both values) and E3-A3 (rig block with the bench start checklist, dry run against `ocb-sim` before the bench).

**Scope: host code + docs + a short macOS bench (H.34) + an owner eye check. No firmware change, no wire change, no core rule change.** In scope: the bottom bar (STOP idle, its "Esc" sub-line, the two-line safety note, three empty reserved slots); `WorkerCommand::Stop` and its handling in the worker; Esc read at the top of every frame (not consumed) and Space consumed there (never activates a button); STOP by click, Enter and AccessKit click; the Tab order with STOP last; `stop` log lines from the app and the worker; host tests (C.28, G.19, G.20) and the H.34 bench. Out of scope: Play from cursor / Play from start / Listen buttons (Epics 5–6; only their slots are reserved), the live STOP style (`button-stop-live`, Epic 6 countdown and Play), the gamepad and anything it holds (Story 4.8: the real "a held input is released by Esc" check belongs to its bench, see Bench decision), sending STOP before closing the port on exit (Epic 6, forward note), issue #45 itself (this story must not make it worse), Windows and Linux runs (issue #43).

## Acceptance Criteria

Numbers marked *(story)* are set by this story; every number is measured as listed in the AC → measurement table.

1. **The bottom bar (UX-DR39, Epic 4 form).** The bottom region (88 pt, `panel-raised`, Story 4.1) is laid out left to right with 16 pt side padding and 14 pt gaps *(story; mock `.bottom{gap:14px;padding:0 16px}`)*: three reserved slots for Play from cursor, Play from start and Listen, each 190 pt wide (`big-button-min-width`), with nothing drawn in them, no AccessKit node and nothing focusable; then the safety note filling the remaining width; then STOP at the right edge. Every element is vertically centred in the bar. At 1024 × 680 and 1280 × 800, ppp 1 and 2, nothing overlaps and everything stays inside the bar.
2. **STOP, idle look (`button-stop-idle`).** STOP is 60 pt high (`big-button-height`), at least 190 pt wide (`big-button-min-width`), content left-aligned at 22 pt padding *(story; mock `.big{padding:0 22px}`)*: the painted ■ (`Symbol::Stop`, 16 pt box *(story; mock svg 16 × 16)*), a 12 pt gap *(story; mock `.big{gap:12px}`)*, then "STOP" in `button-lg` (17 pt, `wght` 700) over the sub-line "Esc" in `button-lg-sub` (12.5 pt, 400) at 85 % opacity *(story; mock `.big small{opacity:.85}`)*; fill `stop-idle-fill`, 1 pt `ember` border (floored to 1 physical px), text and symbol `stop-idle-text`, radius `rounded.xl` (12), the whole button at 75 % opacity (`button-stop-idle.opacity`); no glow. It is enabled and clickable in every state (no disabled look, ever). The focus ring (2 pt `amber`, 2 pt offset, `rounded.xl`) is painted at full opacity when it has keyboard focus.
3. **The safety note.** Two lines, right-aligned against the space before STOP with 6 pt right padding *(story; mock `.safety{padding-right:6px}`)*: "Don't dock the Switch mid-song." over "Esc stops at any time.", Nunito Sans 13 pt, 400, line height 1.35 *(story; mock `.safety{font-size:13px;line-height:1.35}`, new token `typography.safety-note`)*, `text-muted`, the second line at 70 % *(story; mock `.safety span{opacity:.7}`)*. At 1024 pt it may wrap inside its width (EXPERIENCE › Responsive "the safety note wraps") and stays inside the bar. Each line is one `Role::Label` AccessKit node named with its text, not focusable.
4. **Esc is STOP, always (UX-DR41, UX-DR61).** In every mode (main screen and gallery) and every state (no dialog, a dialog open, the firmware dialog arriving in this very frame, a focused widget, a focused text field), a fresh press of Esc (a `Key::Escape` press event with `repeat == false`, any modifiers) is read at the top of `App::ui` in the frame's first pass, before any widget or `Modals::show`, without consuming it. The open dialog, if any, then consumes the same Esc and closes as `Dismissed` (Story 4.3 contract, unchanged; the firmware dialog's opening-frame opt-out of Story 4.6 unchanged). Key-repeat events of a held Esc never request STOP again. At most one STOP is requested per frame, whatever the number of presses and clicks in it.
5. **STOP by mouse, Enter and AccessKit.** A click on STOP, Enter while STOP has keyboard focus, or an AccessKit `Click` on its node requests STOP, exactly once per activation (a held Enter is one activation: its key repeats are dropped at frame start unless a text edit has focus; review decision 2026-11-27). While a dialog is open the scrim takes pointer clicks (Story 4.3 D4), so STOP is reached by Esc then (Open questions 3).
6. **Space never activates a button (UX-DR61, UX-DR62).** Every Space key press event is consumed at the top of the frame's first pass unless a text edit has focus (`Context::text_edit_focused()`): with any modifiers while a widget has focus (Cmd/Ctrl+Space too: buttons activate with Enter only, review decision 2026-11-27), and without Cmd/Ctrl while nothing has focus (Cmd/Ctrl+Space then stays for the OS and later shortcuts). So a focused STOP (or a focused dialog button) is never clicked by Space; Space does nothing else yet (preview arrives in Epic 5).
7. **The worker sends STOP (AD-6, AD-16).** A STOP request becomes `WorkerCommand::Stop` sent with `try_send` (never blocking, AD-16). The worker handles every queued command at the start of its next pass: with a session in `Connected` it calls `Session::stop()`, and the STOP frame is queued to the port in that same pass; in `Stopping` nothing new is sent (the pending STOP keeps its 50 ms resend, Story 3.3); after the ACK the session is `Connected` again (`LinkEvent::Stopped`). The controller then goes NEUTRAL, IDLE, queue cleared, latch cleared (AD-8): every held input is released (host test with an `ocb-sim` controller holding A).
8. **Harmless without a link.** With no bridge (no port), a bridge alone (`Opening`), an incompatible controller (`Incompatible`, C.27 stays green: still no byte written), no worker (`NotStarted`) or a dead worker (`Ended`), a STOP request writes nothing to any port, changes no LED, opens no dialog, never panics and never blocks the UI; it is logged (Log lines). `Opening` needs no frame: every HELLO (≤ 100 ms apart) has STOP semantics on the controller (AD-7; Open questions 2).
9. **AccessKit (Story 4.2: basic).** STOP is one `Role::Button` node named "Stop" (plain case, so screen readers do not spell "STOP") with the description "Esc stops at any time."; a kittest test finds it with `get_by_role_and_label(Role::Button, "Stop")` and reads the description from the AccessKit node. The ■ inside it adds no node (symbol helper variant without `widget_info`).
10. **Keyboard focus order (UX-DR61).** Tab moves focus in region order status → song → note view → gamepad → bottom bar: today that is LED PC↔Bridge → LED Bridge↔Controller → LED Switch → STOP → back to the first LED; Shift+Tab goes the other way. The empty slots and the safety note are never focused. While a dialog is open, Tab stays inside it (Story 4.3, unchanged).
11. **`stop` lines in the log.** Each STOP request writes one app `stop requested …` line, and the worker writes one line per command handled and one per ACK of a STOP it sent for a command, plus the first STATUS after that ACK, in the exact formats of Dev Notes › Log lines, through the existing `LogHandle`s (non-blocking). No line while nothing happens.
12. **No regressions, CI green.** `cargo fmt --all --check`, `cargo clippy --locked --workspace --all-targets -- -D warnings`, `cargo test --locked --workspace`, `cargo deny --locked check licenses bans`, the G.8 scripts, the smoke run (`worker=` ≥ 1) and "ocb-sim never ships" stay green on ubuntu, windows and macos. G.1, G.3, G.10–G.18, C.23–C.27 keep passing (changes only where this story adds tokens, a bottom-bar case or a scan word, with the reason in the Debug Log). Every new check has a red proof in the Debug Log.
13. **Docs, bench and eye check.** `EXPERIENCE.md`, `DESIGN.md`, `docs/test-plan.md` (C.28, G.19, G.20, H.34 and its rig block), `epics.md` (Story 4.8 note) and `app/README.md` updated as in Task 8. H.34 runs on macOS with the dry run green on the bench commit (owner present); Windows/Linux go to issue #43. The owner eye check of the bottom bar is recorded. M5 stays TODO (Stories 4.8–4.9).

## Dev Notes

### Scope in one paragraph

The wire already knows STOP: `ocb-core`'s `Session::stop()` abandons whatever is pending, sends STOP with the next free seq, resends it every 50 ms and sends nothing else until its ACK (Story 3.3, `docs/link-protocol.md` "Rules the app link applies"); the controller executes STOP in any mode and session state (NEUTRAL, queue cleared, IDLE, latch cleared, AD-8), and `ocb-dev` proved it on the real rig (H.25: "STOP ACKed, controller mode Idle"). This story connects it to the user: a STOP button and an always-on Esc in the app, a `Stop` command in the worker, the safety note, the Tab order, Space made harmless, and `stop` log lines that a short macOS bench reads.

### Decisions taken at story creation (change only with a reason in the Debug Log; the owner can overrule any)

- **D1. Esc and clicks are handled in the frame's first pass only.** eframe 0.37 hands input events to the first pass only (`Context::run_dyn` calls `begin_pass(new_input.take())`, checked in `~/.cargo/registry/src/*/egui-0.37.0/src/context.rs:1080-1135`); Story 4.6 discards that pass when the firmware dialog opens. App state changed in a discarded pass is kept (only egui's output is thrown away), so a STOP requested there is sent once, and the second pass cannot request it again (no events). `frame_start` is still guarded by `current_pass_index() == 0` to make the rule explicit.
- **D2. One STOP per frame; key repeats ignored.** A held Esc auto-repeats at the OS rate; each repeat would queue a command and a log line, and in `Connected` after an ACK a new STOP frame. One fresh press = one STOP; several presses or a press plus a click in one frame = one STOP (the first source wins in the log).
- **D3. Esc is read in every mode, also the gallery.** "Esc stops at any time" has no exception; the gallery runs the real worker (`App::new`).
- **D4. With a dialog open, the scrim takes the click (Open questions 3).** egui's `Modal` blocks the layers below and Story 4.3 D4 says a backdrop click does nothing. Esc reaches STOP whatever is open, which is what the safety note says. Drawing STOP above the scrim would be a design change (and a second interactive layer during a modal).
- **D5. `Opening`, `Incompatible`, no port: nothing is written (Open questions 2).** `Opening`: every HELLO (resent every 100 ms) has STOP semantics on the controller (AD-7, `docs/link-protocol.md` "`HELLO` has STOP semantics"), so a frame of our own adds nothing and `Session::stop()` refuses it (`NotConnected`). `Incompatible`: the controller went neutral on the mismatched HELLO and C.27 demands silence. No port: nothing to write to.
- **D6. The pending STOP's 50 ms resend is kept (Open questions 5).** If the controller does not answer (cut off behind the bridge), the session resends STOP every 50 ms until the ACK, a port loss or a controller reboot. That is a core rule (Story 3.3) and the same class of writes as the `Opening` HELLOs (every 100 ms) to a bridge alone. Issue #45 (macOS close blocks when the bridge stops taking bytes) is about the close path and is fixed there (`tcflush` on close); this story records the bound it adds (20 frames/s while unanswered, C.28) and does not change the core.
- **D7. `Space` consumed at frame start in 4.7.** Story 4.3 left it here ("Space is Story 4.7's"): egui fake-clicks a focused clickable widget on Space or Enter (`context.rs:1758-1764`), and STOP is the first focusable button of the main screen. A `TextEdit` with focus keeps Space (none exists yet; Epic 9's editor relies on it).
- **D8. Stable ids and a pure layout.** `bottom_bar::stop_id()` and `bottom_bar::layout()` let G.19/G.20 check geometry and focus without screen scraping; the slots exist only as rects (no node, no focus), so Epics 5–6 fill them without moving STOP.
- **D9. One `Role::Button` "Stop" with a description, symbol without a node.** Story 4.2 basic level; the epic AC fixes the name and description. The description is set with `Context::accesskit_node_builder` right after `widget_info` (egui 0.37 has no description field in `WidgetInfo`; `Response::on_hover_text` would set one from a tooltip, `response.rs:797-812`, and STOP has none).
- **D10. A short macOS bench (H.34).** See "Bench decision".

### Bench decision (E3-A1 / E3-A3)

**A bench is needed, short (about 10 minutes, macOS, owner present): H.34.** Host tests cover the logic end to end on fake ports and the `ocb-sim` controller (C.28, G.20). What only the rig shows: the real winit Esc and mouse click on macOS reach `App::ui` in the first pass and become a STOP, the worker's command path writes STOP to the real bridge, the real controller firmware ACKs it in an open session and stays connected (no `NAK`, no LED change), and the end-to-end time from the key press (the `stop requested` line) to the ACK (`stop acked`) on real USB/UART. Limit 100 ms (NFR-05's neutral budget as a ceiling; expected a few ms: one worker pass ≤ ~2 ms plus the UART round trip at 460800 baud).

**What "inputs held" means in 4.7.** Nothing in the app can hold an input before Story 4.8 (the gamepad). Holding one with `link_probe.py` before starting the app does not carry over: the probe must quit first (the port is exclusive), and its exit drops DTR (DIRECT abort, AD-5) and stops its PINGs (app timeout 1 s), so the controller is already neutral when `bonooru` opens. H.34 therefore tests STOP as **reaching, ACKed, harmless and idempotent** on the real controller, with the controller's IDLE after the ACK (`stop after … mode=idle`) as the proxy for "released" (AD-8: entering IDLE always publishes NEUTRAL). The real "held input is released" check moves to Story 4.8's bench (Task 7, Task 8.3).

**What H.34 does not do, on purpose.** No bridge-alone step (`Opening`): it would only show `stop skipped reason=opening` (host-tested in C.28) and ends with stopping an app whose bridge has no controller, which is the issue #45 setup. The step with the bridge unplugged comes before any app restart, and the app is stopped with the bridge plugged and the controller connected.

**Dry run.** `g20_h34_dry_run` replays the H.34 steps on a fake worker with an `ocb-sim` controller and prints the expected `stop` lines; it must be green on the bench commit (rig block item 5).

### Log lines (AC 11; kind tag `stop`; the bench reads exactly these)

App (UI thread, `App::log`):
- `requested source=<esc|button> dialog=<open|none> command=<queued|no_worker|worker_gone|queue_full>` (`dialog=open`: a dialog was open or requested in that frame; it usually takes the same Esc, but not the firmware dialog in its opening frame nor an Esc with Cmd/Ctrl). Example: `2026-11-28T10:15:02.123Z +842ms stop requested source=esc dialog=none command=queued`.

Worker (`WorkerCore::log`):
- `sent port=<p>` — `Session::stop()` called in `Connected`.
- `pending port=<p>` — a STOP already waits for its ACK (`Stopping`); nothing new sent.
- `skipped reason=<no_port|opening|incompatible|closed> port=<p|->` — nothing written.
- `acked port=<p> after_us=<n|-> by=<command|session>` — `LinkEvent::Stopped`; `after_us` from the first unanswered `Stop` command to the ACK on the worker clock (`-` for `by=session`). `by=command` whenever a `Stop` command was handled since the STOP went out, also when the session had started that STOP itself (abandon, `PLAYBACK_DONE`); `by=session` only for a STOP no command touched.
- `after port=<p> mode=<idle|direct|playing|0x<hh>> abort_count=<n>` — the first STATUS after such an ACK (`0x<hh>`: a mode this app does not know, `Mode::Unknown`).

The app's `requested` line and the worker's line for the same request may land in the log in either order (two threads, one FIFO log; the worker can handle the command before the app's line reaches the log channel).

Patterns (`tests/common::line_matches` style; no regex crate): `requested` + `source` OneOf[esc, button], `dialog` OneOf[open, none], `command` OneOf[queued, no_worker, worker_gone, queue_full]; `sent`/`pending` + `port` non-empty; `skipped` + `reason` OneOf[no_port, opening, incompatible, closed] + `port`; `acked` + `port` + `after_us` DigitsOrDash + `by` OneOf[command, session]; `after` + `port` + `mode` OneOf[idle, direct, playing] or `0x<hh>` + `abort_count` Digits. (`port` values contain `/`: add a `Pat::NonEmpty` if needed.)
