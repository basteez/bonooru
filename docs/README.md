# docs

Reference documentation agents and contributors read during development (link protocol, test plan, input mechanics). The design history lives in the author's notes; planning artifacts live in `_bmad-output/`.

## Reference docs

- [link-protocol.md](link-protocol.md): framed binary protocol between the host app and the controller board, through the bridge.
- [usb-controller-emulation.md](usb-controller-emulation.md): USB controller profiles, HID report, descriptors and timing chain toward the Switch 2.
- [score-format-and-mapping.md](score-format-and-mapping.md): score pipeline, mapping profile (TOML) and text score format.
- [ocarina-input-mechanics.md](ocarina-input-mechanics.md): how the game's ocarina is played with buttons and modifiers, plus unknowns to measure.
- [test-plan.md](test-plan.md): spikes, timing validation and acceptance tests.
