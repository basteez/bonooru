# app

Cross-platform desktop app in **Rust + egui/eframe** (ADR-008, accepted 2026-11-20): bridge auto-detection, score import (text + MIDI), timeline preview, playback, virtual gamepad, built-in flasher. Crates and layout: AD-18 and `app-stack-options.md` in `_bmad-output/planning-artifacts/architecture/architecture-bonooru-2026-11-19/`. Feasibility evidence: `spikes/app-egui/SPIKE-REPORT.md`.

## Layout

A Cargo workspace (Story 3.2), Rust pinned to 1.100.0 by `rust-toolchain.toml`:

- `core/`: crate `ocb-core`, the GUI-free core (AD-18): no egui/eframe, no threads, no I/O; its only runtime dependencies are `toml` and `serde`, exactly pinned (Story 5.1). Today it holds `protocol` (COBS, CRC-16/CCITT-FALSE, frames, the receive splitter, the canonical state and every message) and `version` (the app version from `git describe`, fallback `0.0.0-dev`). `link` is the sans-IO session (Story 3.3): HELLO and INFO, go-back-N with credits, STOP, PING and typed events; bytes and a µs clock in, bytes and events out. `profile` (Story 5.1, AD-17) is the only mapping-profile parser: TOML text in, the integer `schema` checked and migrated, every key required and unknown keys refused, value rules (ranges, the AD-15 floor of two frames, every pitch of the range fingered), a typed `Profile` or `ProfileError` out; `resolve` picks the user copy with the bundled default's name and game version over the bundled default, and reports refused and ignored files.
- `sim/`: crate `ocb-sim`, dev-only and never shipped: a fake controller that follows `docs/link-protocol.md`, an impaired channel (drop, bit flip, junk, duplicate, reorder) and a driver on a fake clock. The session tests C.6 to C.11 live in `sim/tests/`; Story 3.4 uses it for the dry run of `ocb-dev`.
- `gui/`: crate `ocb-app`, the desktop app (Story 4.1), binary `bonooru`; the only crate that depends on egui. eframe and egui are pinned at `=0.37.0` with default features off (`accesskit`, `clipboard`, `default_fonts`, `wgpu`, `x11`: no `wayland`, no `system_fonts`); on Linux the app forces winit's X11 backend (AD-18). Modules: `ui::theme` (every `DESIGN.md` token, the single source), `ui::fonts`, `ui::layout` and `ui::main_screen` (the five main-screen regions), `ui::paint` (painter-level helpers that handle egui's limits once: focus ring, glow, text halo, dashed rects, convex-only fills, stroke floor, digit cells, corner brackets, the dialog flourish; no accessibility nodes), `ui::symbols` (the 14 painted symbols), `ui::widgets` (themed button, standalone symbol and time, each one accessible node), `ui::modal` (the modal dialog and `Modals`, the app's one-at-a-time dialog host), `ui::status_strip` (`src/ui/status_strip.rs`, Story 4.5: the brand and the three status LEDs, each focusable with its tooltip and one `Role::Status` node), `leds` (`src/leds.rs`, Story 4.5: the LED decisions as plain data, no egui: the latest worker snapshot, the time since it arrived and the worker's health → three LEDs, their copy and the `led` log lines), `gating` (`src/gating.rs`, Story 4.6, 4.8: the gate as plain data, no egui: whether the worker, the three LEDs or a required firmware update block the gamepad and Play (six reasons in precedence order), the once-per-connection trigger of the firmware dialog, its copy and the `gate` log lines), `ui::firmware` (`src/ui/firmware.rs`, Story 4.6: the OK-only "Firmware update needed" dialog), `stop` (`src/stop.rs`, Story 4.7: STOP as plain data, no egui: who asked, what became of the worker command, the `stop requested` line and the bottom bar's copy), `ui::keyboard` (`src/ui/keyboard.rs`, Story 5.0: every keyboard rule in one table, the only module that reads egui key events: at frame start Esc read for STOP without being consumed, Space consumed so it never clicks a focused button, Enter repeats dropped, Listen on Space and the global Cmd/Ctrl shortcuts recognised; in the gamepad pass the 18 gamepad keys by physical key (read only while the panel has focus; mapped keys without Cmd/Ctrl consumed), the focus keys and the panel's focus lock; the key releases `App::logic` honours; the dialog's answer keys and Esc), `ui::bottom_bar` (`src/ui/bottom_bar.rs`, Story 4.7: the bottom bar's pure layout, the safety note and STOP, `widgets::stop_button`, with the three Play/Listen slots reserved and empty), `gamepad` (`src/gamepad.rs`, Story 4.8, 4.9: the virtual gamepad as plain data, no egui: the 16 controls and two sticks, the mouse semantics (a click is a tap of at least 50 ms, holds, sticks), the 18 keyboard keys (`PadKey`: fresh presses, a key tap of at least 50 ms, chords, key holds apart from the mouse hold), the release rules, the one canonical state sent on change (the union of every hold), the copy and the `pad` log lines), `ui::gamepad` (`src/ui/gamepad.rs`, Story 4.8, 4.9: the gamepad panel: tab, caption, the pad drawn from the tokens with the mock's geometry, key chips, legend and the gate's inline hint; the compact button grid with key-hint tooltips below 1280 pt; the panel is one focusable `Role::Group` node, parent of every panel node, with the inset amber ring, wash and "Keys active" chip while it has keyboard focus; senses the pointer, every control one AccessKit node, none focusable), `ui::gallery` (the hidden debug gallery), `cli`, `smoke`.
- `services/`: crate `ocb-services` (Story 4.4), what the app does besides drawing; no egui. `profiles` (Story 5.1): the bundled mapping profile embedded read-only, the OS config dir (macOS `~/Library/Application Support/Bonooru`, Windows `%APPDATA%\Bonooru\config`, Linux `$XDG_CONFIG_HOME/bonooru`), the user copies in `<config dir>/profiles/*.toml` (any case, no dot-files; regular files of at most 1 MiB, anything else refused unread), the settings file name `<config dir>/settings.toml` (apart from the profiles; nothing reads it yet), and the `profile` log lines the app writes at start (`profile loaded name="…" game_version="…" schema=… source=<bundled|user> file=<"f"|->`, `profile refused file="f" reason=<read|parse|schema|invalid> detail="…"`, `profile ignored file="f" reason=<other_identity|duplicate>`; names and details quoted, control characters as spaces). `port` (the traits the worker talks to and the real `serialport` 4.10.1 adapter: 460800 8N1, DTR asserted then the input cleared, writes that drop instead of blocking, the handle dropped on the first hard error), `log` (the rotating `bonooru.log`, 1 MiB × 4 files, on its own thread behind a bounded queue), `worker` (the serial worker: one thread named `bonooru-serial` owns the port and the link session, lists ports every second, opens only `Ours`/`Unconfirmed` bridges by the `ocb_core::device` rules, follows the bridge by its serial number; the UI gets events and immutable snapshots over `crossbeam-channel`) and, with the dev-only feature `sim`, `sim` (fake backends for tests and dry runs, never in a shipped build).
- `tools/ocb-probe/`: crate `ocb-probe` (Story 4.4), dev-only and never shipped: the discovery bench tool. It runs the same worker and log headless and prints machine-checkable lines (`list`, `run`, `run --expect-permission-denied`, `alone`; see `--help` and `docs/test-plan.md` H.28 to H.31). CI builds it in release mode for Windows x64, Linux x64 and arm64 and macOS arm64 (job `probe-artifacts`, artifacts `ocb-probe-<os>-<arch>`), so a bench machine needs no Rust.
- `profiles/`: the bundled default mapping profiles (TOML, one per game version, AD-17); the first, `oot-switch2-1.1.1.toml`, comes from Story 1.5. Not a crate.

## Running the app

From `app/`:

```sh
cargo run -p ocb-app                    # the main screen
cargo run -p ocb-app -- --gallery       # the hidden debug gallery (design review)
cargo run -p ocb-app -- --smoke-test    # 3 frames, one OCB_SMOKE ok/fail line: exit 0 ok, 4 fail, 3 watchdog (60 s)
```

If `cargo` is not on your `PATH` (rustup installed without `~/.cargo/bin` in the shell profile), put the toolchain first, e.g. `export PATH="$HOME/.rustup/toolchains/stable-aarch64-apple-darwin/bin:$PATH"` on an Apple Silicon Mac, or build once and run the binary directly: `cargo build -p ocb-app` then `target/debug/bonooru --gallery` (from `app/`).

The gallery shows every token, then one section per painting helper (focus ring, glow, halo, dashed rects, convex fills, stroke floor, digit cells, the 12 symbols, corner brackets) and buttons that open two sample dialogs.

The app starts the serial worker at launch (Story 4.4): it finds the bridge by itself (USB `2E8A:000A`, product `Bonooru Bridge` where the OS reports it) and never asks for a port. The smoke line ends with `worker=<scans>` (at least 1). The log is `bonooru.log` in the OS log directory: macOS `~/Library/Logs/Bonooru/`, Windows `%LOCALAPPDATA%\Bonooru\logs\`, Linux `$XDG_STATE_HOME/bonooru/logs/` (default `~/.local/state/bonooru/logs/`); it rotates at 1 MiB and keeps three old files (`bonooru.1.log` to `bonooru.3.log`). On Linux, opening the bridge needs the user in the group of the device node (`dialout` on Debian, Ubuntu and Fedora, `uucp` on Arch); the app says so and never asks for privileges. Every change of a status LED is written to the same log as one `led` line (`led <link>=<state> name="<name>" reason=<reason> status_age_us=<n|-> session_age_us=<n|->`, ages in µs, one line per change of state, name or reason, Story 4.5), next to the worker's port and version lines. Every change of the gate (Story 4.6, 4.8) is one `gate` line (`gate gamepad=<on|off> gamepad_reason=<r|none> play=<on|off> play_reason=<r|none> controller_proto=<n|-> app_proto=<n|->`, `r` one of `worker`, `no_bridge`, `bridge_not_ready`, `firmware_update`, `controller_link`, `switch_not_ready`), and the firmware dialog writes `dialog shown id=firmware_update_needed connected_us=<n> …` when it is requested (once per mismatching connection: again after a bridge replug or a restart) and `dialog closed id=firmware_update_needed outcome=<primary|dismissed>` when OK or Esc closes it. STOP requests and their handling appear as `stop` lines in `bonooru.log` (Story 4.7): the app writes `stop requested source=<esc|button|gamepad> dialog=<open|none> command=<queued|no_worker|worker_gone|queue_full>` for each Esc press or STOP activation (at most one per frame, key repeats ignored; `dialog=open`: a dialog was open or requested in that frame, which usually but not always takes the same Esc), the worker `stop sent|pending port=<p>`, `stop skipped reason=<no_port|opening|incompatible|closed> port=<p|->`, `stop acked port=<p> after_us=<n|-> by=<command|session>` (`by=command` whenever a Stop command was handled since the STOP went out, also when the session had started that STOP itself; `by=session` only for a STOP no command touched) and `stop after port=<p> mode=<idle|direct|playing|0x<hh>> abort_count=<n>` (the first STATUS after the ACK; `0x<hh>` is a mode this app does not know). Within one request, the app's `requested` line and the worker's `sent`/`pending` line may be written in either order (two threads, one log). `SetState` commands and their handling appear as `pad` lines, controller mode changes as `mode` lines in `bonooru.log` (Story 4.8): the app writes `pad press control=<c> source=<mouse|accesskit>`, `pad release control=<c> reason=<pointer_up|tap|window_blur|stop|gate|controller_idle>`, `pad stick=<left|right> start`, `pad stick=<s> end reason=<…>`, `pad ignored control=<c|stick_left|stick_right> reason=<gate reason|busy>` (`busy`: the pad already holds an input) and `pad command=<queue_full|no_worker|worker_gone>` (a press line always before the state it causes is sent); with the keyboard (Story 4.9, only while the gamepad panel has keyboard focus) `pad press control=<c> source=keyboard key=<k>`, `pad release control=<c> reason=<key_up|tap|focus_lost|window_blur|stop|gate|controller_idle>[ key=<k>]`, `pad ignored control=<c> reason=<gate reason> key=<k>` (a key press while gated), `pad stick=<s> end reason=<focus_lost|layout|…>` (`layout`: the window turned compact during a drag), `pad keys=on source=<click|tab|other>` and `pad keys=off reason=<esc|dialog|window_blur|elsewhere>` (the panel gained or lost keyboard focus; `k` is `arrow_up`, `w`, `l`, `enter`, `backspace` …); the worker writes `pad sent port=<p> buttons=0x<hhhh> hat=<n> lx=<n> ly=<n> rx=<n> ry=<n>` (the state was handed to the session; with a `Stop` taken in the same pass only the STOP frame goes out), `pad dropped reason=<no_port|opening|incompatible|closed|stopping|no_link|not_ready|busy|bad_state|not_connected> port=<p|->[ action=stop]` (`action=stop`: a release refused while the session is connected, so the worker sent STOP instead) and `mode port=<p> from=<m> to=<m> abort_count=<n>` (one per change of the STATUS mode, none for the first STATUS of a session). `stop requested source=gamepad` is the STOP the gamepad requests when the gate turns blocked while it holds an input.

## Running the probe (bench)

From `app/` (or the unpacked CI artifact on Windows and Linux):

```sh
cargo run --release -p ocb-probe -- list          # every serial port, its USB ids and class; never opens a port
cargo run --release -p ocb-probe -- run           # connect, unplug, replug, log check (prompts on screen)
cargo run --release -p ocb-probe -- alone         # the bridge without a controller: HELLO only
cargo run --release -p ocb-probe -- run --expect-permission-denied   # Linux, H.30
```

Exit codes: 0 PASS, 1 FAIL, 2 usage, 130 interrupted. Every verdict line has a dry run (`cargo test -p ocb-probe -- --nocapture run_pass` prints what the bench shows).

`gui/ci/check-smoke.sh <file> <backend-regex>` re-checks a smoke line (CI); `gui/ci/check-accesskit.sh [target...]` checks that ocb-app enables eframe's `accesskit` feature in the normal dependency graph (CI, G.8). On Linux the build needs `pkg-config` and `libudev-dev` (Fedora: `systemd-devel`; serialport's port enumeration, run time `libudev.so.1`) and the X11 development packages listed in the `app` CI workflow (`.github/workflows/app.yml`, step "Linux system dependencies").

## Checks

Run from `app/` (the same gates as the `app` CI workflow on ubuntu, windows and macos):

```sh
cargo fmt --all --check
cargo test --workspace                       # C.1 to C.25, G.1 to G.6 and G.10 to G.13 in docs/test-plan.md
cargo clippy --workspace --all-targets -- -D warnings
cargo deny check licenses bans               # NFR-07 allow-list and the AD-21 network-crate ban, deny.toml
```

`cargo test` reads the shared conformance vectors in `firmware/common/proto/vectors/` (AD-14): the app and the firmware codecs must agree on every one of them.
